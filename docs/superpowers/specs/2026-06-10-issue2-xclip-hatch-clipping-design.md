# 이슈2: XCLIP 해치 경계 기하 클리핑 — 설계

- 날짜: 2026-06-10
- 상태: 사용자 승인됨 (브레인스토밍 + 디바이스 진단 후)
- 브랜치: `fix/issue2-xclip-hatch-bleed` (main에서 분기, PR #4 머지 후)

## 1. 문제 (실측 확정)

사용자 파일 `01. 건축도면-1.dwg`(S21+)의 건물배치도 시트에서 **회색 반투명 사다리꼴이
표제란(DRAWN BY/건물배치도/CODE NO.)을 덮는다.**

진단 결과 (에뮬레이터 + 임시 DIAG 로깅, 정량 일치):

- 배치도의 지도는 **XCLIP(SPATIAL_FILTER)된 INSERT**의 자식.
  클립 윈도우 = `(11870755,-726345)~(12050755,-590095)`, 오른쪽 끝이 표제란 왼쪽 경계와 일치.
- 도로 솔리드 해치(모델 인덱스 96943, bbox `(11857069,-699774)~(12073069,-680899)`,
  216,000×18,875)가 클립창을 **오른쪽으로 22,314 / 왼쪽으로 13,686 유닛 침범.**
- 현행 `write_entity`의 HATCH 클립 처리(dwg_serialize.c)는
  ① 완전 밖 → 컬링, ② 클립크기 **이상** overflow → 컬링, ③ **부분 침범 → 무클립 통째 emit.**
  이 해치는 ③ → 클립 오른쪽(표제란)으로 채움이 번짐.
- 침범폭 22,314 × 화면스케일 0.0363 px/unit ≈ 810px ≈ 사용자 스크린샷 블롭 폭 실측 816px.
- 같은 클립의 라인류는 Liang-Barsky로 잘리므로(Phase 9.4) 라인은 안 번짐 — 증상과 일치.

기각된 가설: 도면↔원점 걸침 엔티티(DIAG2 스캔 결과 0건), fillLines 경계 탈출(0건),
깨진 해치 경계(폴리곤 시각화 결과 정상 도로 형상, 자기교차 미미 2건뿐).

## 2. 목표 / 비목표

**목표**: XCLIP 활성 시 해치의 솔리드 채움·패턴 라인·경계 stroke가 클립창 밖으로
나가지 않게 한다 (AutoCAD XCLIP 의미론과 동일).

**비목표 (범위 외)**:
- WIPEOUT 마스킹 (별건, Phase 10.5에서 의도적 skip 유지)
- 사용자 스크린샷의 세로 흰 선 (사용자가 타깃에서 제외)
- 비-XCLIP 해치의 도면영역(displayExtents) 클리핑 — 진단 결과 그런 침범 엔티티 없음
- gradient fill

## 3. 설계

### 3.1 클립 함수 (신규, dwg_serialize.c)

Sutherland–Hodgman 폴리곤 클리핑을 축정렬 사각형에 적용:

```c
/* 닫힌 루프(2n doubles, world)를 사각형 [x0,x1]×[y0,y1]로 클립.
 * pts_io/np_io 를 클립 결과로 교체(기존 버퍼 free). 결과 <3점이면 루프 드롭(np=0). */
static void clip_loop_to_rect(double **pts_io, int *np_io,
                              double x0, double y0, double x1, double y1);
```

- 내부: 반평면 4회 패스 (x≥x0, x≤x1, y≥y0, y≤y1). 패스당 출력 ≤ 2n점 버퍼.
- **빠른 경로**: 루프 bbox가 클립창에 완전 포함 → 무변경 (이 파일의 다른 정상 해치
  3개는 모두 이 경로라 바이트 단위로 무영향).
- 볼록 클립영역에 루프별 클립이므로 even-odd 채움 의미론 보존 (clip 경계 위 점들의
  ray-parity 불변). 스캔라인 fillLines 생성도 같은 루프를 쓰므로 일관.

### 3.2 write_hatch 연결

루프 빌드 직후(`build_one_loop` 호출 뒤), `g_clip_on`이면 각 루프에
`clip_loop_to_rect(..., g_clx0, g_cly0, g_clx1, g_cly1)` 적용.

- 이후 단계(emit_defline_fill의 fillLines 생성, 루프 emit)는 클립된 루프를 사용
  → 채움·패턴·경계 모두 자동으로 클립창 안으로 제한.
- 드롭된 루프는 nv=0으로 emit (디코더 `repeat(0)` → 빈 path, 렌더러 `size<2 continue`
  — 기존 코드가 이미 안전 처리).
- 프로토콜/디코더/모델/렌더러 **무변경**.

### 3.3 기존 휴리스틱 정리 (write_entity HATCH case)

- `outside`(완전 밖) 컬링: **유지** (싼 early-out).
- `overflow`(클립크기 이상) 컬링: **제거** — 진짜 클리핑이 대체. 예전에 통째로
  사라지던 극단 overflow 해치도 이제 클립창 안 부분은 정상 표시.

## 4. 에러 처리

- malloc 실패: 클립 스킵하고 원본 루프 유지 (현행 dbuf 패턴과 동일한 보수적 폴백).
- 퇴화 루프(<3점, 면적≈0): 드롭.

## 5. 검증 (evidence-based)

1. **정량**: 임시 DIAG 로그로 H[96943] bbox가 클립창 안(`minX ≥ 11,870,755`,
   `maxX ≤ 12,050,755`)으로 줄어드는지 확인.
2. **무회귀**: 단위테스트 전체 통과, 사용자 파일 엔티티 수 101,603 유지,
   ref.dwg 로드 (overflow 컬링 제거로 해치 수 증가 가능 — 회색 띠 재발 없는지 시각 확인).
3. **시각**: 에뮬레이터 fit 스크린샷에서 배치도 도로 밴드가 클립 경계에서 끊김.
4. **최종**: 실폰(S21+) 사용자 파일에서 표제란 블롭 소멸 — 사용자 확인.
5. 임시 진단 코드(Kotlin DIAG2/DIAG3, native DLOG) 전부 제거 후 커밋.

## 6. 리스크

- S-H가 클립 경계를 따라 인공 엣지 생성 → 경계 stroke가 클립선 위에 그려짐.
  AutoCAD도 XCLIP 절단면에서 해치가 잘린 모습을 보이므로 시각적으로 동일/자연스러움.
- overflow 컬링 제거로 ref.dwg 등에서 이전에 숨겨졌던 해치가 (클립되어) 나타남 —
  의미론적으로 더 올바른 결과지만 시각 회귀 확인 필요 (검증 2).
