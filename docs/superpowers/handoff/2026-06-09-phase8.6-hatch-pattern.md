- 날짜: 2026-06-09
- 브랜치: `feat/hatch-pattern-rendering`
- 스펙: `docs/superpowers/specs/2026-06-09-hatch-pattern-rendering-design.md`

## 결론

비솔리드 HATCH가 경계선만 그려지던 것을 **임베드된 패턴 정의선(`deflines`)으로 실제 채움
라인(ANSI31·AR-RROOF 등)을 렌더링**하도록 구현 완료. 패턴명 하드코딩 없이 모든 패턴 일반 지원.
줌 인지 게이트로 멀리서는 반투명 솔리드, 가까이서는 실제 패턴 라인 — Phase 10 성능 유지.

## 무엇을 했나 (커밋 순서, 브랜치 `feat/hatch-pattern-rendering`)

1. `7ab8f27` 프로토콜 v2 + `DxfHatch` 확장 + `decodeHatch` (Kotlin, TDD, 단위테스트 +3)
2. `dbe4074` native 경계 테셀레이션 헬퍼 (DBuf/`emit_arc`/`emit_bulge`/`build_one_loop`)

4. `869b708` 렌더러 줌 게이트 + `drawHatchFillLines`

## 아키텍처 (구현된 대로)

`DWG → write_hatch`가 로드 시 1회:
- 경계 루프를 affine 변환해 월드 점열로 구성 (라인/폴리라인+bulge/원호 테셀레이션,
  타원호·스플라인은 chord 근사 + `patternFallback`).
- 각 def-line을 월드로 변환(pt0/단위방향/offset에 affine → 블록 변환 흡수) 후, 방향=u·수직=v
  좌표계로 회전해 평행선을 수평선(v=k·off_v)으로 단순화. 각 라인의 경계 u-교차점을 even-odd로
  페어링한 내부 구간에 dash(없으면 솔리드) 배치.
- 밀도 캡: `HATCH_MAX_FILL_SEGMENTS`(4000)/`HATCH_MAX_FAMILY_LINES`(20000) 초과 시 `patternFallback`.

payload(v2): `isSolid u8 | patternFallback u8 | minLineSpacingWorld f64 | num_paths + 경계 |
num_fill_segments + (x1,y1,x2,y2)…`. 디코더가 `DxfHatch(isSolid, patternFallback, minLineSpacing,
paths, fillLines)`로 읽고, 렌더러 `drawHatch`가 `screenSpacing = minLineSpacing × scale` 게이트
(≥3px이면 패턴 라인, 미만/폴백/솔리드면 25% 반투명 솔리드).

## 검증 (증거 기반)

- **단위테스트**: `./gradlew :app:testDebugUnitTest` → 77 tests, 0 failures (hatch 디코드 3개 추가).
- **빌드**: `assembleDebug` BUILD SUCCESSFUL (3 ABI).
- **디바이스 통합** (에뮬 `emulator-5554`, API 36, `ref.dwg` 13MB):
  - 로드 성공 — `dwg_read_file rc=68, num_objects=110111`, `hatch=160`, `serialized 17.7MB`,
    `SUCCESS — 192882 entities`, 크래시/버전불일치/디코드 예외 **없음** → v2 프로토콜 동기 확인.
  - **좌표계 캘리브레이션 (수치, 임시 native 로그로 실측)**:
    - `ANSI31` (ndash=0, 솔리드 라인): a0=90.00°/180.00°, off=(317.5,0)/(0,-317.5), spacing=317.5,
      nfill=160/9, fb=0 → 솔리드 대각/축 라인 정상 생성.
    - `AR-RROOF` (ndef=3, ndash=4, 점선 지붕패턴): a0=45.00°, spacing=1701.8, nfill=5~19, fb=0.
    - 모든 각도 깨끗(45/90/180°), spacing 양수(모델단위 mm), nfill>0, **폴백 0** → **def-line은
      모델공간 해상 형태로 직접 사용 가능**(entity `angle`/`scale_spacing` 추가 적용 불필요),
      우리 변환 정확, 클리핑이 경계 내로 세그먼트 생성(폭발/누출 없음).
  - 캘리브레이션용 임시 변경(렌더러 게이트 -1.0, native `android/log.h` 디버그 로그)은 **revert 완료**
    (`git checkout`), 최종 커밋 코드로 빌드+테스트 재확인 통과.

## 알려진 한계 / 범위

- **타원호·스플라인 경계**: chord 근사 + 솔리드 폴백(패턴 미적용). 현행 대비 회귀 아님.
- **밀도 초과 hatch**: 솔리드 폴백(캡 4000 seg/hatch).
- **gradient fill / MPOLYGON**: 범위 외(현행 동작 유지).
- **직렬화 크기**: `ref.dwg` 6.2MB→17.7MB (패턴 채움 세그먼트 추가분). 메모리 영향 미미, 캡으로 상한.

## ⚠️ 함정 메모

- native `.so` 변경 시 `adb install -r`로는 갱신 안 됨 → **uninstall + install** 필수.
- 에뮬 storage 부족 시 install 실패(`INSUFFICIENT_STORAGE`) → 대용량 앱(gms/vending) `pm clear`로 확보.
- adb로 파일 열기: file:// 은 scoped storage로 EACCES → MediaStore content URI
  (`content://media/external/downloads/<id>`) + `--grant-read-uri-permission` 사용.
